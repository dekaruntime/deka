# React 919 — disposable spike

**Result: one DekaScript component renders through react-dom SSR and live Ink,
including an Ink prop update.** Released **deka + dsc 0.50.0** perform acquisition,
integrity verification, checking and emission. **Node 26.3.1 executes the emitted
module** through a small host adapter. This is a renderer feasibility result,
not a claim that native Deka can host Ink today or that typed React integration
is complete. No product paths, compiler/runtime code, package.json, npm install,
or resurrected ui package are involved.

Refs: [deka#919](https://github.com/dekaruntime/deka/issues/919),
[accepted rfd#64 and Sami's five answers](https://github.com/dekaruntime/rfd/issues/64),
[summon rfd#39 and its ratified amendment](https://github.com/dekaruntime/rfd/issues/39).

## Reproduce

From the repo root (Node >=22.15 with `module.registerHooks`, Python 3, curl):

```sh
bash spikes/react-919/install-toolchain.sh
bash spikes/react-919/verify.sh
node spikes/react-919/bench.mjs
cd spikes/react-919
/usr/bin/script -q evidence/ink-pty.txt env NODE_ENV=production node run.mjs ink
```

The installer copies the repository CI dsc installer into an ignored directory
with a **local** 0.50.0 pin (the repo pin stays 0.49.0), and verifies both released
binaries against their release manifests. No Rust build or global installation.
After installing tools, verification/rendering needs no network. `deka install
--locked` checks every vendored hash before execution; run it before using the
harness directly. The loader enforces locked names, not integrity by itself.

`verify.sh` checks the DS component and readable summon wrapper, reproduces five
negative compiler probes, compares fresh emitted output against the committed
snapshot, then asserts HTML and both Ink frame contents. `evidence/` contains
actual output, diagnostics, full timing samples and a PTY transcript. Ink debug
mode emits successive full frames without separators; repeated text is expected.
The PTY capture may include the macOS `script` stdin EOF marker.

## What actually renders

`Component.dsx` is the **only application component**, with typed props, a fragment,
`stack`, `text`, and a dynamic child. Its unchanged emitted module is loaded by
both runs. The component is passed to `React.createElement(Greeting, props)`;
it is never called manually to fake a render.

- `ui/jsx` resolves only inside the spike loader to `jsx-adapter.mjs`.
  `jsx(tag, props, child)` becomes `React.createElement(type, props, child)`;
  `jsxs(tag, props, children)` spreads the array; Fragment is React.Fragment.
- Web maps `stack`/`text` to `section`/`span`, then react-dom/server calls
  `renderToString`. Actual HTML is in `evidence/ssr.html`.
- TUI maps the same tags to small function components backed by Ink Box/Text.
  Ink's real react-reconciler and Yoga render to a live output stream. `rerender`
  changes `message`, and the capture asserts the updated text before unmounting.
- Both renderer imports resolve React to the same `@js/react` vendor within each
  process. There is no second embedded React or hand-written tree traversal.
  Each renderer has its own renderer implementation; “shared reconciler” means
  the React component/element model, not sharing a Fiber root between platforms.
  SSR does not test browser reconciliation/hydration.

`stack` and `text` are provisional spike labels, **not** the deka ui API or a new
HTML DSL. Real component imports, props and platform semantics remain design work.

## Vendoring and the precise workarounds

`vendor-inputs/sources.json` records original CDN URLs and SHA-256 hashes.
`vendor-inputs/*.mjs` preserve the fetched bytes. The Ink source map and extracted
source inventory expose the frozen embedded dependency set, including reconciler,
scheduler, Yoga (inlined WASM), terminal utilities and optional devtools residue.
The react-dom 19.1.1 metadata declares scheduler ^0.26.0, so rfd#64's zero-dependency statement does not hold for the full react-dom package (this spike uses its server build). The CDN bundles are opaque acquisition units, not individually version-locked
source packages. The source map does not contain source text. Metadata snapshots
and core licenses are included; a full transitive source/version/license audit
remains necessary before real integration. Neither fetching a CDN bundle nor
summon's import check proves library correctness or totality.

`vendor.mjs` deterministically prepares these bytes and calls **deka summon once
per prepared module** using file URLs. React uses a jsDelivr ESM build; react-dom
server and Ink use esm.sh Node bundles. There is no npm command or node_modules.
Prepared sources live in ignored `.cache/prepared`; their final bytes are committed
under `js_modules`, with `deka.json` and `deka.lock` generated by summon.

Only module specifier strings change in foreign bundles:

1. React imports route to `@js/react` (including its bundle require dispatcher).
2. Node built-in imports route to explicit `@js/host-*` modules. These expose the
   real Node namespaces supplied by the harness before vendor loading; they are
   not polyfills, sandboxing, or a portable runtime implementation.
3. Optional react-devtools-core routes to a throwing `@js/devtools-disabled` shim.
   Devtools are disabled; invoking them fails loudly. No React, reconciler, Yoga,
   or Ink renderer is stubbed. Optional bundled ws/devtools residue is retained.

The file-URL provenance in the lock refers to this checkout's preparation paths.
Normal replay uses committed bytes and never opens those URLs. A fresh-directory replay reproduced all 22 locked file-hash maps (`evidence/vendor-replay.txt`). To re-acquire in a
**fresh disposable copy**, remove only its generated `js_modules`, `deka.lock` and
manifest dependencies, then run `node vendor.mjs`. Its local source URLs change
with location; resulting file integrity must match. Summon deliberately refuses
to overwrite an existing vendor name. Do not run vendor.mjs over the committed set.

## Findings on 0.50.0

| Needed / observed | Evidence and minimal workaround |
| --- | --- |
| JSX in public `.ds` | `probes/jsx.ds` fails: `JSX is only allowed in .dsx files`. Use compiler-requested `Component.dsx` for the spike; public-extension policy remains unresolved. |
| Checkout's `export function` syntax | `probes/function.ds` fails after `export`; released grammar accepts `export fn ... Component`. This is checkout/toolchain documentation drift, not a React problem. |
| React JSX factory | Actual output imports `jsx`, `jsxs`, `Fragment` from `ui/jsx`, not the docs' `deka.ui` global. No React factory flag is exposed in transpile help. Loader maps that exact import to our adapter without modifying emitted code. |
| Bundled JSX target | `dsc bundle` succeeds but embeds legacy `createComponentNode`/`jsx(tag, props)`; emitted third-argument children are discarded. `evidence/native-bundle.mjs` and `native-bundle-tree.json` show the root Fragment with `children: []`. Use preserved emission plus the React adapter; do not use the bundled result. |
| Dynamic child | `props.message` emits `live(function() { return props.message; })` from `ui/reactive`. Adapter evaluates it during the React component render; React rerender drives updates. No old signals runtime is restored. This does not validate all reactive expressions or hooks. |
| Stable IDs / props | Emitter adds `data-deka-id`. Web forwards these attributes; Ink wrappers consume only children and discard them. Key/ref/events/children-prop spread semantics need a separate integration contract. |
| `summon ... from "@js/react"` | `probes/react-at-js.ds`: verifier requires a literal relative `.mjs` path, despite pm supporting `@js/`. Use relative path for boundary experiments; host loader handles `@js/` for JS execution. |
| Named `createElement` export | `probes/react-relative.ds` needs `createElement(tag: string): Exception<ReactNode, JsError>`; fails `export is not a statically verifiable function` against the aliased CDN export. `summon infer` skips all React exports (including createElement/useState). |
| Default / namespace shape | `probes/react-default.ds` tries `default(): Exception<ReactNamespace, JsError>`; parser accepts the name but verifier rejects the non-function namespace object. This is not a truthful callable signature and cannot declare React's namespace. JSX runtime subpaths are also unsupported by pm; this spike needs only createElement, not react/jsx-runtime. |
| Readable function boundary | `probes/react-wrapper.mjs` declares `createText(text)` calling real React.createElement. Matching Exception/opaque declaration **passes** verification (`react-wrapper.ds`). Shape can be exposed with a small wrapper; alias analysis and namespace/value support remain gaps. No dishonest `total` claim. The main JSX path still uses host glue, not this unused probe. |
| Raw CDN dependencies | Original Ink summon fails with `react`, a devtools URL and 17 `node:*` imports (full list in evidence). No automatic fetch or import rewrite is performed. Explicit frozen bundles/specifier preparation is required. |
| Native Node imports | Even `node:*` is treated as unresolved by summon. The 18 explicit host bridges are a spike workaround, not an approved product capability surface. |
| CDN basename / infer | Direct React `+esm` URL becomes `@js/-esm`; prepared react.mjs supplies a useful name. Summon emits “write your summon block”; it does not auto-scaffold. dsc summon infer exists in 0.50.0, contrary to the checkout docs, but cannot infer these bundled exports. |
| Native Deka execution | `.mjs` run entry rejected. `deka-entry.js` reaches `run.mjs` then fails resolving `node:module` even with `--allow-all`. This proves this Node harness is not natively runnable; it does not inventory every Ink runtime compatibility gap. Node is the explicit execution workaround. |

No typed state hooks, rules-of-hooks enforcement, error boundaries, accessibility,
keyboard input, focus, hydration, islands, mobile, desktop shell or product bundling
is claimed. A changing prop proves a real Ink update, not DS useState support.
The preliminary default probe intentionally asks for an invalid callable shape to
locate the namespace mismatch; it is not a proposed declaration.

## Performance sniff

10 sequential fresh Node processes per renderer, warm OS file cache, production
vendor builds, macOS 25.6.0 x64, Intel i9-10910, Node 26.3.1. Medians below; full
samples/ranges in `evidence/perf.json`. Timed dynamic imports include the spike host bridge (static harness imports are outside that interval);
process wall includes launch and shutdown. Ink uses debug frame output and one
next-event-loop turn to observe each committed frame. This is a tiny two-line UI.

| Measurement | SSR | Ink |
| --- | ---: | ---: |
| Import/setup | 64.0 ms | 146.0 ms |
| First render/commit | 3.23 ms | 20.22 ms |
| Warm render (100 iterations per process) / one update | 0.027 ms | 2.20 ms |
| Whole process wall | 199.7 ms | 349.2 ms |

Committed vendor bytes (raw / gzip): React **11,701 / 4,447**;
react-dom **server** **181,209 / 54,910**; Ink with embedded dependencies
**383,530 / 130,989**. Host bridges, source archives and harness are excluded.

RFD #64 mentions react-dom ~130 KB versus prior 10.7 KB emitted pages; it does
**not** give numeric startup/render times or an Electron measurement. Our server
bundle is not the browser react-dom client, and the RFD does not specify encoding
or equal functionality. These sizes therefore do not establish a regression
ratio, hydration cost, or continued Electron advantage. Measure the actual browser
client/island bundle and a matched desktop workload before making those claims.

## Recommended integration order

1. Preserve the accepted language-first train (indexing, Option erasure, summon
   migration). Align released JSX extension/import contracts and compiler docs.
2. Join pm `@js/` resolution to dsc verification; support verifiable re-export
   aliases, necessary value/default/subpath shapes and readable wrappers. Freeze
   a reviewable dependency graph with complete provenance, including Yoga WASM;
   define host builtin capabilities instead of adopting this global bridge.
3. Add a React createElement/Fragment emitter target, remove legacy `live` lowering
   for it, settle props/children/key/ref and statically enforce hook placement.
   Expose state as checked summoned functions. Keep the shared React version and
   identity explicit at every renderer entry.
4. Validate the real Deka runtime against SSR and Ink dependencies, then ship a
   small semantic Stack/Text/Button vocabulary with web/TUI mappings, events,
   focus, failure boundaries and meaningful conformance cases.
5. Retain SSR and add client hydration at explicit island roots with one shared
   React client module; no per-island React copies. Measure browser payload/startup.
   Run the deferred mobile feasibility prototype and matched webview/Electron
   comparison separately. This spike does not resurrect the deleted framework.
