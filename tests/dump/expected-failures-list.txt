# Known-failure ratchet for tests/dump (deka#906 follow-up).
#
# This is DEBT, not a suppression list. Every slug below is a fixture that
# currently fails outright (summary.overall.fail) on the dump gate -- a
# pre-existing backlog, not something newly broken. Listing it here means the
# gate does not block release on this specific already-known set of failures.
#
# It does NOT mean "ignore forever":
#   - A slug that starts PASSING must be removed from this file in the same
#     PR that fixed it. A listed slug that now passes is a hard gate failure
#     (a "stale" entry) -- exactly like the divergence ratchet in
#     expected-failures.txt applies to divergences. The gate silently
#     agreeing with debt that no longer exists is how bit rot hides.
#   - A slug that fails and is NOT listed here is a hard gate failure (a new,
#     unbudgeted failure). Only pre-existing failures get a pass.
#
# This file must never be grown casually to make CI green. Adding a slug here
# to unblock an unrelated PR is band-aiding a regression, not managing debt --
# fix the regression instead. Only add an entry alongside a comment/issue
# explaining why it is pre-existing debt, not new breakage.
#
# This is a SEPARATE axis from expected-failures.txt (which tracks host
# DIVERGENCES -- wasm and native disagreeing). This file tracks fixtures that
# fail outright, independent of divergence. Do not merge the two lists.
#
# Generated 2026-09-14 from a real `bun run dump` against testsuite
# corpus-v0.53.0 + dsc v0.53.1 (see PR body for the run). 71 entries, matching
# the release run this ratchet was introduced to unblock (run 34909498831:
# overall(pass=824 fail=71 divergent=25 skip=0)).
#
# Updated 2026-09-15 (refs #1059): @deka/crypto 0.4.2 and @deka/time 0.3.2
# annotated their own bridge-wrapping exports with explicit return types
# (dsc#223 <infer>-assignability fix), and @deka/tcp 0.2.1 / @deka/tls 0.2.1
# did the same -- but the tcp/tls fix was invisible until a second,
# unrelated bug was also fixed: deka.gg's served registry index
# (public/api/registry/*.json in dekaruntime/website) is a checked-in probe
# snapshot, decoupled from the candidate-version list in data/registry.ts,
# and the version-list commit was never followed by a probe regen -- so
# production kept 404ing on tcp/tls 0.2.1 even after the tarballs landed in
# R2 (website#154 fixed this).
#
# Net effect on this baseline: only 5 of the 71 entries actually cleared,
# NOT the 31 predicted for the whole <infer> group. Verified with a real
# native+wasm dump run (bun tests/dump/scripts/dump-results.mjs) against the
# now-current registry: overall(pass=829 fail=66 divergent=25 skip=0).
# Removed below: crypto-digest-unknown, crypto-random-bytes-length,
# crypto-random-bytes-rejects-zero, tcp-listen-then-close,
# tcp-set-deadline-zero.
#
# Why the other 26 <infer> fixtures in the original group did NOT clear:
# @deka/jwt 0.4.1 and @deka/http 0.4.1 declare EXACT (not ranged) internal
# dependency pins -- jwt's deka.json pins "@deka/crypto": "0.4.1" and http's
# pins "@deka/tcp"/"@deka/tls": "0.2.0". Republishing crypto/tcp/tls does not
# cascade to them; jwt/http still transitively install the old, unfixed
# leaf versions until THEIR OWN manifests are bumped and republished. This
# falsifies the "http and jwt need no changes; they resolve transitively"
# assumption in the #1059 diagnosis -- confirmed by inspecting the published
# tarballs' deka.json directly. The remaining crypto-* failures split into
# two different causes: crypto-aes-roundtrip / crypto-sha256-abc / (and
# fs-hello-utf8, a different package) fail on a LOCAL bare `unsafe {}` block
# inside the fixture's own .ds source, not the stdlib package -- a
# testsuite-repo fix, out of scope here. time-sleep-ms-* now fail on a
# DIFFERENT, previously-masked error ("expected argument type `string`,
# found type `number`") from `echo()` in @deka/io receiving the numeric
# match-arm result of the now-Result-wrapped `sleep_ms` -- a second,
# unrelated bug uncovered once the <infer> error stopped hiding it. Per
# task scope, none of these are fixed here -- only the 5 confirmed-passing
# slugs are removed.
