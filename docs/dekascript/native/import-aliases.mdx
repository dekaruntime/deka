---
title: "Importing nominal types through barrels"
---

An imported enum, struct or newtype keeps its declaring type when you rename
its export or import. A barrel can forward the type and its factory together.
The factory's arguments and return type follow the same imported binding.

`library.ds`:

```ds
type ProjectId number;
export {ProjectId};
export fn makeId() ProjectId {
    return ProjectId(42);
}
```

`index.ds`:

```ds
export {ProjectId as default, makeId} from "./library.ds";
```

`main.ds`:

```ds
import {echo} from "io";

import type {default as Id} from "./index.ds";
import {makeId} from "./index.ds";

fn main() void {
    const id: Id = makeId();
    echo(string(unboxNumber(id)));
}
```

`deka check main.ds --entry main` succeeds and `deka run main.ds --entry main`
prints `42`. Built executables preserve this behavior after source deletion.
Multiple renamed barrels work the same way. Types from different declaring
modules remain distinct even when their original names match; renaming an
import does not make those types interchangeable.

An `import type` binding remains usable only as a type. Import an enum's
constructor as an ordinary value when you need to construct its cases.

Multiple local names for the same declaration also retain its identity; see
[local type aliases](./local-type-aliases).
