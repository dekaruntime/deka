---
title: Reflection with getType()
description: .getType() returns a first-class Type value describing a value's runtime type; super fn makes a type parameter's static descriptor available at compile time.
---

Every value answers the question "what are you?" at runtime. Calling
`.getType()` returns a **first-class `Type` value** — not a string —
matching Java's `getClass()`, C#'s `GetType()`, Go's `reflect.TypeOf()`,
and Python's `type()`.

```ds
const t = "hello".getType()
echo(t.toString()) // "string"
```

## The descriptor

`getType()` returns a frozen, interned descriptor:

```ds
{ kind, name, toString() { return this.name } }
```

- `kind` is an open set: `"string"`, `"number"`, `"boolean"`, `"bytes"`,
  `"array"`, `"struct"`, `"newtype"`, `"enum"`, `"option"`, `"object"`,
  `"function"`, `"none"`, `"unknown"`. Only `"string"`, `"number"`,
  `"boolean"`, `"bytes"`, `"array"`, `"struct"`, `"newtype"`, `"enum"`,
  `"object"`, `"function"`, and `"none"` are produced today.
- `name` is what `toString()` returns. Structs, newtypes, and enums report
  their own name; arrays report `"Array"`.

Two honest limitations of runtime inspection:

- An array's element type is not knowable at runtime — `[1, 2]` can only
  report `Array`, never `Array<number>`. Finer descriptors are the static
  trees `super` emits (below).
- Enum-tagged values report through the enum tag path: `Some(1).getType()`
  reports the name `"Option"`, matching the static type.

Descriptors are interned: one singleton per `(kind, name)` per module, so
identity comparison works.

```ds
echo(string("a".getType() == "b".getType())) // "true"
```

In this slice only `toString()` is exposed on `Type`. The rest of the
descriptor API — `name`/`kind` properties, field and case walking,
construction from library code — is deferred (see below).

## Union receivers: the headline case

A union value is one of its members at runtime, and `.getType()` tells you
which — no narrowing required:

```ds
let something: number | string = "hello world"
echo(something.getType().toString()) // "string"
something = 42
echo(something.getType().toString()) // "number"
```

This is the difference between the declared type and the runtime type:
the value's static type stays `number | string` while `getType()`
reports what the value actually is.

## Generics work without `super`

Because the descriptor comes from inspecting the receiver value at
runtime, `.getType()` works on generic type parameters with no additional
keyword or capability:

```ds
fn id<T>(x: T) Type {
  return x.getType()
}

echo(id("hi").toString()) // "string"
echo(id(1).toString())     // "number"
```

## How it compiles

`.getType()` is a compile-time rewrite, exactly like extension methods on
primitives (deka#527): `x.getType()` becomes a call to a module-local
free function, `__deka_type_of(x)`. There is no prototype mutation and no
`globalThis` write. Chaining falls out for free — the outer call is an
ordinary method call on the real descriptor object:

```ds
echo("hi".getType().toString()) // compiles to `__deka_type_of("hi").toString()`
```

A user-declared method or extension named `getType` shadows the builtin,
consistent with the extension shadowing rule.

## Deferred

The following are explicitly out of scope for this slice and land with
the `super` lane or later:

- `super fn` and `T.type()` — the static descriptor for a type parameter
  at a call site. (Landed; see below.)
- `.signature()` — the declared type of a value as opposed to its runtime
  type.
- Walking descriptor fields/cases for schema validation.
- Constructing `Type` values from library code (an open question in
  rfd#41).

## super: types that survive erasure

`.getType()` inspects a *value* at runtime. Sometimes the compiler already
knows the type at a *call site* and you want that knowledge inside the
function — the classic case being generic validation:

```ds
super fn validate<T>(json: string) Type {
  return T.type()
}

echo(validate<User>("{}").toString()) // "User"
```

Marking a function `super` (only plain functions: not structs, constants,
receiver methods, or closures) lets its body mention the type parameters
*as types*: `T.type()` yields the descriptor for the argument the caller
passed. The function is still generic and still erased — no
monomorphization — but the compiler emits one hidden descriptor parameter
per type parameter and rewrites every call site to pass the type's
descriptor as a statically emitted, frozen, module-local constant. Two
calls with the same type receive the identical object.

`super` is marked on the function, not on type parameters, and it does
not propagate: `validate<User>(json)` just works, with no annotation at
the call site. This mirrors the design rule behind `Send` in Rust, in
reverse: `Send` must propagate because it is a proof obligation the
compiler must thread everywhere; `super` is only information retention —
the compiler already knows the type's shape at the call site and is
merely choosing to emit it. Needing call-site annotations or transitive
propagation would be the model telling you it is wrong.

Because the descriptor arrives as an ordinary parameter, it flows through
recursion and closures for free: `validate<T>(x)` inside `validate`
forwards the parameter unchanged, and a closure inside a super fn
captures it like any other value. A super function cannot be used as a
value (`const f = validate` is a compile error) — its emitted signature
has an extra leading parameter, so every reference must be an explicit
call like `validate<User>(json)`. Likewise, a type parameter can only be
passed through from inside another `super fn`; an erased generic function
has no descriptor value in scope to forward.

### Static trees

The static descriptor has the same `{ kind, name, toString() }` triple as
the runtime one, so the two are interchangeable, and composite types
expose their structure:

- structs: `fields: [{ name, optional, type }]` (embedded structs appear
  as required fields),
- enums: `cases: [{ name, payload }]`,
- arrays and options: `elem` / `inner`,
- newtypes: `repr`,
- unions: `members`.

This is what the schema endgame needs: unlike the runtime descriptor, a
static `Array<number>` tree knows its element type.

### Limits and holes

- A type the compiler cannot describe is an error at that specific call
  site, not a viral constraint: function-valued types, types derived
  from `unsafe`, and recursive types are rejected where they are named.
- Inside a super fn, `x.type()` on a concrete receiver is also allowed
  and emits a static tree of the receiver's type. Outside a super fn,
  `.type()` is rejected — for runtime inspection use `.getType()`.
- `super unsafe<T>` (rfd#41's future assertion-closing form) and the
  interaction between `super` and `unsafe { }` blocks are unspecified;
  nothing is designed or promised there.
- Property-form `T.type` (no call) has no super meaning and falls through
  to ordinary field-access errors.
