---
title: Initialize a project
---

`deka init` scaffolds a DekaScript app-router project. Run these commands in an empty directory:

```sh
deka init
deka serve
```

Init prints at most three lines: a ready note, then `deka serve` and `deka dev`
(or `cd <dir>` then `deka serve` when you passed a directory). The home page
responds with HTTP 200, displays **Deka App**, greets **Hello, World.**, and
hydrates a counter island.
Its stylesheet is served at `/style.css`.

The tree matches RFD 24:

```
.
├── app/
│   ├── layout.dsx      # required chrome into #app
│   ├── page.dsx        # the `/` screen
│   └── not-found.dsx   # 404 inside the layout
├── src/
│   └── ui/
│       └── Counter.dsx # client island (`useState` + JSX)
├── public/
│   └── style.css       # copied to the site root as-is
├── index.html          # the document (holes for head / app / scripts)
├── deka.json           # type serve, mode ds
├── deka.lock
└── .gitignore
```

`deka.json` selects DekaScript serving (`serve.mode: "ds"`). There is no
`serve.entry`: the app-router matcher is the entry. Edit `app/page.dsx` to
change the page. The `dev` task is `deka serve --dev`.

`public/index.html` is a compile error — it collides with the root document.
`api/` is the server-handler tree; init does not create it empty. Add
`api/<name>/route.ds` when you need a route.

Running `deka init` again preserves existing files.

The generated `.gitignore` covers `ds_modules/`, `dist/`, `.cache/`, and the
package-manager backup files `.deka.json-backup-*` / `.deka.lock-backup-*`.
