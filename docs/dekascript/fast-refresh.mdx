# Fast Refresh

`deka dev` hot-swaps React components without losing sibling or own state
when the [react-refresh](https://github.com/facebook/react/tree/main/packages/react-refresh)
rules allow it. A non-refreshable edit (a changed non-component export, or a
hook-order change that the runtime cannot recover) falls back to a full reload.

This is the HMR half of the React execution bar (deka#936). Production
`deka serve` / `deka build` resolve `@js/react`, `@js/react/jsx-runtime`,
`@js/react-dom/server`, and `@js/react-dom/client` as runtime builtins
(rfd#64 amendment 2).

## What you do

Write a function component. In development, edit its JSX and save:

```js
import { useState, createElement as h } from "react";

export function Counter() {
  const [n, setN] = useState(0);
  return h("button", { onClick: () => setN(n + 1) }, String(n));
}
```

A sibling `Label` edit must keep `Counter`'s `n`. That is the demo.

DekaScript `.dsx` components work the same way. The dev compile asks dsc for
**jsxDEV** emission with real source locations (`fileName` / `lineNumber` /
`columnNumber` of the opening `<`):

```ds
export fn Card(props: { title: string }) ReactNode {
  return <p>{props.title}</p>;
}
```

Expected dev output (shape):

```js
import { jsxDEV } from "@js/react/jsx-dev-runtime";
export function Card(props) {
  return jsxDEV("p", { "children": props.title }, undefined, false, {
    fileName: "Card.dsx",
    lineNumber: 2,
    columnNumber: 10
  }, this);
}
$RefreshReg$(Card, "Card");
```

`@js/react/jsx-dev-runtime` resolves through the injected import map to the
copy of React shipped with `deka dev`.

## How it is wired

1. **Dev compile** of `.ds` / `.dsx` passes `dsc transpile --dev` when the
   compiler supports it (dsc main after #197, plus a `--dev` CLI flag; published
   0.51.2 has the `CompileOptions.dev` API but not the CLI flag).
2. **Registration.** Each served module is wrapped with the `$RefreshReg$` /
   `$RefreshSig$` contract. Component detection uses exported PascalCase
   functions **and** a `ReactNode` / `Component` return type when the source
   has one.
3. **WebSocket.** A refreshable file change recompiles that module and pushes
   `{ "type": "js-update", "modules": [{ "id", "url" }] }` on `/_deka/hmr`.
   The client `import()`s the new URL and calls `performReactRefresh()`.
4. **Fallback.** Missing boundary, non-component export, or a thrown refresh
   performs `location.reload()`, matching Vite plugin-react.
5. **Server HTML.** An app-router `.ds` / `.dsx` edit that is not an island
   module re-renders the page and pushes `{ "type": "html-update", "html" }`
   on `/_deka/hmr`. The dev client morphs `document` against that markup
   and **leaves hydrated `<deka-island>` subtrees untouched**, so island
   React state, scroll position, focus, and form values outside islands
   survive. Editing an island's own module (`client:load` / `idle` /
   `visible`) full-reloads — morphing cannot refresh `hydrateRoot`.

Generated app-router HTML responses include `Content-Type: text/html`, so
`deka dev` can inject its HMR client. Fragment responses use
`application/json`. The watcher evicts stale server isolates before notifying
browsers, so an immediate reload sees the saved source.

## React in this lane

React 19.1.1, react-dom 19.1.1, and react-refresh 0.17.0 are vendored as
development ESM under `/_deka/react/` (js_modules-style frozen hashes and
licenses in `crates/http/vendor/react/`). Production run/serve/bundle use a
separate always-on builtin graph (`@js/react*`, rfd#64 amendment 2) so
development React bytes stay out of the production CLI.

Do not add a project `npm` dependency on React for `deka dev`.

## Manual check

The automated gate covers registration, the `js-update` payload, a
Playwright sibling-state run (`tests/dump/scripts/fast-refresh-e2e.mjs`),
and server-HTML morph (`crates/cli/tests/server_fast_refresh.rs`): edit a
server-rendered heading while a `client:load` counter is at 3 and a form
input outside the island holds a typed value — the heading updates, the
counter stays 3, the input keeps its value, and CDP records no frame
navigation. Editing the island module itself full-reloads.

To see client Fast Refresh: `deka dev` on a project that mounts a
component from `/_deka/hmr/module/...`, click a counter, edit a sibling
component's JSX, confirm the counter does not reset.

## Building the dev server

Release binaries and default source builds include the development server:

```sh
cargo build --release -p cli
```

`deka dev` and `deka serve --dev` are available out of the box. Development
React is used for Fast Refresh; production builds still emit production React.

For a native-only CLI without the development server, build the CLI package
explicitly rather than the workspace (where Cargo unifies dependency features):

```sh
cargo build --release -p cli --no-default-features --features native
```

This optional build retains `deka serve`, but invoking `deka dev` or
`deka serve --dev` reports the missing feature. `scripts/check-prod-react-bytes.sh`
checks that this native-only binary excludes the frozen development React DOM
source; the CLI's `react_builtin` integration tests check emitted production
JavaScript independently of which features the CLI includes.

In development mode, `/_deka/` vendor, module, and HMR WebSocket requests
bypass the per-IP rate limiter without consuming application request tokens.
Other paths remain limited. In production, `/_deka/` has no exemption and
development endpoints remain unavailable. This uses runtime configuration;
there is no environment-variable switch for disabling the limiter.
