---
title: Compiling an executable
description: Package a DekaScript entry and the Deka runtime into one executable for the current platform.
---

`deka compile <entry.ds>` produces a self-contained executable for the platform
running the command. It invokes dsc to transpile and bundle the entry, then embeds
that JavaScript in a copy of the running Deka executable, including V8.

```ts
// hello.ds
import { echo } from "io"

echo("hello from compiled Deka");
```

```sh
deka add @deka/io
deka compile hello.ds --outfile hello
./hello
```

Standard output:

```text
hello from compiled Deka
```

The default output path is `./deka-app`. Existing output files are rejected;
choose another path or remove the old output before rebuilding. Compilation
errors return a nonzero exit status and do not publish an executable.

The produced executable runs from another directory without the original `.ds`
files, dsc, or a separate Deka installation. It materializes the embedded bundle
in a temporary directory at startup, so the host needs writable temporary storage.
Program output and exit status follow normal runtime execution.

Compilation needs dsc: set `DEKA_DSC`, install it beside Deka, or put it on `PATH`.
On macOS, compilation also uses `/usr/bin/codesign` to ad-hoc sign the executable
after embedding the payload. This is a local executable, not a notarized app.

This first cut targets only the current host platform and architecture; there is
no `--target` option. Runtime data files are not included by this command.

## Desktop apps (`--desktop`)

`deka compile --desktop` packages a DekaScript web project as a native desktop
app whose window is a webview showing the same React output the browser would
render. There is no npm, no `package.json`, and no `@tauri-apps/cli` step: `deka`
drives the Tauri-stack webview (wry + tao) itself.

```sh
deka compile --desktop --outfile MyApp
DEKA_DESKTOP_DUMP=1 ./MyApp
```

Dump-mode standard output (CI / headless check):

```text
__DEKA_DESKTOP_DUMP__
React island
Hello from Deka desktop
```

What `deka` does, in order:

1. Run the same web pipeline as `deka build --bundle` in the project (requires
   `deka.json` `type: "serve"`, `deka.lock`, `app/`, and `public/`).
2. Start `deka serve` long enough to snapshot `/` (React SSR HTML, including
   island markers) and every local `src` / `href` asset that document references.
3. Embed those bytes in a copy of the running Deka executable.

Launching the produced binary opens a native window and serves the snapshot over
a custom `deka://` protocol. Client React (`hydrateRoot`, islands) runs in the
webview. Set `DEKA_DESKTOP_DUMP=1` to print `document.body.innerText` and exit
instead of leaving the window open.

This first cut launches the webview on macOS only. Packaging the snapshot works
on any host; opening the window on Linux or Windows is a follow-up. There is no
`.app` / `.exe` / AppImage matrix, no `--target`, and no npm-based Tauri project
generation.
