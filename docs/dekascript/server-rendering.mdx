---
title: Server Rendering and Hydration
description: React server rendering and hydration of compiled DekaScript islands.
---

App-router pages render through production React (`@js/react-dom/server`).
Components marked `client:load`, `client:idle`, or `client:visible` are
islands: the `@js/react/jsx-runtime` wrapper places each function component
inside a `<deka-island>` container with serialized props. The shared client
bundle hydrates that container with the same compiled component the server
rendered.

## API

| API | Purpose |
|-----|---------|
| `deka.ui.renderToString(node)` | Synchronously render a React node; returns `{ html: string }`. Requires React SSR to be initialized. |
| `deka.ui.renderToStreamHtml(node)` | Returns a promise for the rendered HTML string, not a streaming response. |
| `jsx`, `jsxs`, `Fragment` from `@js/react/jsx-runtime` | Create React nodes; the compiler emits imports from this module. |
| `hydrateRoot` from `@js/react-dom/client` | Hydrate an island's `<deka-island>` container in the browser. |

The frozen `globalThis.deka.ui` object contains `signal`, `effect`, `memo`,
`createSignal`, `createEffect`, `createMemo`, `renderToString`, and
`renderToStreamHtml`. JSX factories, `Fragment`, and `hydrateRoot` are module
exports, not members of that namespace.

## Server rendering

Function components receive props and return React nodes. JSX compiles to
`jsx` or `jsxs` calls with children in the props object; fragments use the
imported `Fragment`. For example, this is JavaScript at the React module boundary:

```js
import { jsx, jsxs, Fragment } from "@js/react/jsx-runtime";
import { renderToString } from "@js/react-dom/server";

function Greeting(props) {
  return jsx("h1", { className: "greet", children: "Hello " + props.name });
}

const html = renderToString(jsxs(Fragment, {
  children: [jsx(Greeting, { name: "Deka" }), jsx("p", { children: "Welcome" })]
}));
// <h1 class="greet">Hello Deka</h1><p>Welcome</p>
```

Here the imported React `renderToString` returns a string. The host's
`deka.ui.renderToString` wraps the rendered string in `{ html }`.
React handles text and attribute escaping, boolean attributes, and void tags.

## Islands and hydration

Apply `client:load`, `client:idle`, or `client:visible` to a function component.
For example, `app/page.dsx` can render an imported counter:

```ds
import { Counter } from "../src/ui/Counter.dsx"

export fn Page() ReactNode {
  return <Counter start={5} client:load />
}
```

With a `Counter` that renders a button containing its initial count — including
a live signal read such as `{count()}` — the served HTML is:

```html
<deka-island data-deka-island="Counter" data-deka-directive="load" data-deka-props="{&quot;start&quot;:5}" style="display:contents"><button data-deka-id="Counter:Counter/i0" type="button">5</button></deka-island>
```

The JSX runtime wraps function components, not primitive tags. The compiler's
`data-deka-id` identifies the inner host element; the wrapper's
`data-deka-island` identifies the component for hydration. Props are JSON in an
HTML-escaped attribute, not base64 in HTML comments. The wrapper removes the
three directives from the component's props and excludes `children`, `key`,
`ref`, and function or symbol values from the serialized props. Pass
JSON-serializable data to islands.

`deka serve` injects the shared runtime:

```html
<script type="module" src="/assets/islands.js"></script>
```

`deka build` emits the same shared runtime under a content-hashed filename in
`dist/client/assets/`, such as `islands.9361b10245.js`. Serving the built artifact
uses that hashed URL in the script tag.

The bundle includes the compiled island components and production React,
including `hydrateRoot` from `@js/react-dom/client`. Its hydration loop reads
`data-deka-island`, looks up the component in the generated registry, parses
`data-deka-props` with `JSON.parse`, and calls `hydrateRoot(node, jsx(Component,
props))`. The browser does not need a separate React install.

All three directives currently use this same immediate hydration loop. The
emitted `data-deka-directive` records `load`, `idle`, or `visible`, but the loop
does not defer hydration until idle time or visibility.
