---
title: Rust UI development and hot reload
---

Install the Rust development command from this checkout once:

```sh
cargo install --locked --path crates/deka_ui_dev
```

In an application that depends on `deka-ui`, run:

```sh
cargo deka dev
```

Cargo's package, binary, example, and feature options select the application.
For the desktop counter in this repository:

```sh
cargo deka dev --locked -p deka-ui --example tour-counter
```

The command enables `deka-ui/hot-reload`, builds the native debug application,
and watches workspace and local path-dependency Rust sources and manifests. Saving `view!` markup patches
its retained nodes on the existing application's next development turn. Static
elements, scalar attributes, `class` utilities, and quoted text can change.
The application and supervisor classify the whole local source snapshot before
patching, after a short save-stability check. Existing interpolations, handlers,
and component invocations keep their compiled bindings and state. Components
and reactive child slots can reorder or move between static parents without
being constructed again. Empty conditional slots remember their new insertion
position when a later signal update makes them visible. Static element `id`
attributes help retain identities across sibling rearrangements. Give repeated
component invocations distinct literal `id` props when reordering or moving them;
otherwise identical compiled slots use the restart path.

A successful patch prints:

```text
deka dev: patched 1 template(s); state preserved
```

A handler, function, import, type, or other compiled-code edit triggers a Cargo
build, then replaces the application process. The terminal announces the
restart and that signal state resets. A failed build keeps the old process and
prints Cargo's diagnostics; the next corrected save retries the build.
Malformed markup also keeps the complete last good tree and reports its error.

Literal props on `#[component]` call sites can change in place. Supported scalar
parameter types are `String`, `&'static str`, `bool`, `char`, Rust integers and
floats. Direct markup attributes/interpolations and reads inside `move` event,
attribute and child closures update through typed slots. The component's local
signals and existing handlers survive. For example, changing `step=1` to
`step=2` changes the existing handler's increment without resetting its counter:

```rust
#[component]
fn Counter(title: String, step: i32) -> View {
    let mut count = signal(0);
    view! { <button onClick={move |_| count += step}>"{title}: {count}"</button> }
}
// Inside another view!:
// <Counter title="Count" step=1/>
```

A prop used to initialize state or calculate ordinary Rust values outside a
reactive closure requires rebuilding. Forwarding an owned prop into another
component, shadowed or mutated prop variables, receiver methods on props, opaque Rust macros using props,
custom prop types, changed literal kinds/suffixes and out-of-range values also
use the explicit fallback. All prop values and every mounted template are
checked before the batch changes any nodes or signals.

Newly added or removed Rust expressions, changed compiled expressions, opaque
fragments whose structural registrations cannot be relocated, a changed template
root count/kind, builder decorations chained after `view!`, and changes to a
static class base combined with compiled class toggles also rebuild. Nested
markup inside an opaque Rust child expression or component invocation rebuilds;
independent `view!` bodies inside a component can patch. A fallback keeps the
complete previous tree until a successful rebuild; it never applies just the
supported parts of that save.

For a plain Cargo process without automatic rebuild/restart, explicitly enable
the development feature:

```sh
cargo run --features deka-ui/hot-reload
```

It patches supported markup and reports when a rebuild is required. Use
`cargo deka dev` for the automatic process replacement.

For browser development, install the matching binding tool and the WASM target:

```sh
cargo install --locked wasm-bindgen-cli --version 0.2.128
rustup target add wasm32-unknown-unknown
cargo deka dev --web --locked -p deka-ui-tour --example hot_reload_web --port 3000
```

Open the printed loopback URL. Select a `cdylib` library or example exporting
`start(canvas)` through `wasm-bindgen`, using `deka_ui::launch` to mount into the
provided canvas. For the tour's `start(lesson, canvas)` export, add
`--lesson counter`. `--port 0` chooses an available port.

The development server watches the same workspace/local dependencies and sends
source-template patches to the existing browser application. Its normal frame
scheduler repaints the canvas and accessibility controls. Markup patches preserve
signals, handlers and component identities; compiled-code changes rebuild WASM
and reload the page, resetting state. Failed builds or malformed edits retain
the last good module and UI. New connections replay the current templates.

Release native and browser applications compile out source payloads, template
metadata, polling, patch machinery and the browser connection, even with the
feature enabled. Custom application profiles that enable debug assertions are
development builds.
